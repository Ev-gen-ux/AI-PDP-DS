# Совместимость и выпуск

Версия относится к конкретной библиотеке. Для кодовой поставки имя пакета берётся из её package.json; новый компонент/расширение API требует соответствующего changeset. Совместимый ремонт — patch, совместимое расширение — minor, несовместимый контракт — major. Документ/внутренняя правка без публичного влияния может иметь No public API impact. Для Figma-only версия, изменения и миграция фиксируются в проектных release notes без требования npm-пакета/changeset.

Совместимость включает props, поведение, CSS-роли и layout. Release note отражает компонент, тип изменения, влияние, миграцию и проверку. Changelog/невыпущенные заметки сохраняются; среда разработчика не публикуется вместо системы.

Conventional Commits и review/PR применяются при порученном Git-действии; наличие этого стандарта не поручает commit/push. CI и защищённые настройки читаются фактически, без предположения по историческому списку jobs.

Перед кодовым выпуском пройти предусмотренные format/typecheck/lint/test/build/consumer/Storybook и ручные критерии. Для Figma проверить целевую библиотеку, свойства/привязки, шрифты, темы и визуальные критерии; для both — обе стороны и паритет. Проверка архива/публикация/визуальная приёмка — отдельны. Публикация только в предоставленном scope; токен не печатается. Отдельный runtime публикации не меняется попутно с Node22 development профилем.
