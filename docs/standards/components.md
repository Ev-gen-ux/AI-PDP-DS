# Компоненты React web

Компонент реализует принятый Spec выбранной системы. Публичные props/defaults/варианты/экспорты и числовые значения берутся из него; существующий код и соседний компонент не заменяют согласованный источник.

- Строгие TypeScript-типы и публичные экспорты. Не обходить ошибки через any, ts-ignore или отключение проверок.
- Реализация, stories, index и требуемый mapping находятся рядом. Формат mapping определяется реальным Code Connect профилем; metadata-заготовка не считается опубликованным шаблоном.
- Для текущего React-профиля используется styled-components, css helper, полные variant maps, transient $props. Служебные props не попадают в DOM; !important не применяется.
- В компонентах семантические токены. Новое значение сначала проходит источник/генерацию; производные CSS/TS не редактируются вручную.
- Новый prop/вариант или изменение визуального/API-контракта сначала заносится в Spec и согласовывается. Для локального ремонта сохраняется принятый контракт вне scope.
- Простой элемент не получает compound API без причины в анатомии. Составные компоненты используют существующие примитивы.
- Родитель владеет семантикой своего тела. Вложенные Label, Inline Message и прочие DS-компоненты сохраняют собственные props/токены; дублировать или перекрашивать их семантику в родителе нельзя.
- Иконки используются через существующий Icon-слой системы, с явным size map из Spec; разработка новых иконок/графиков требует отдельного явного поручения.

Обязательны применимые [tokens](tokens.md), [accessibility](accessibility.md), [documentation](documentation.md), [Figma](figma.md), [quality](quality.md) и [releases](releases.md). Особенности конкретной системы находятся в её собственных конвенциях внутри проекта.
