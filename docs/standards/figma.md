# Figma и соответствие

Источник существующего визуального контракта — актуальный master и принятый Spec. Для code-first согласовать источник значений и визуальную приёмку. Недоступная Figma не разрешает угадывать числа.

До визуальной реализации Spec содержит применимые варианты/состояния, padding T/R/B/L, gap, radius, font-size/line-height и цепочку источник → токен → resolved value. Отдельно проверить radius каждого размера. State Token Matrix связывает фон, border, label, icon и геометрию; Hard Constraints фиксирует неизменяемое. Разные роли текста/иконки получают соответствующие карты.

Матрица соответствует props/style maps/stories; новая ось вносится до кода. Строковые имена Figma сохраняются в mapping 1:1. Сверяются реальные enabled/hover/active/focus/disabled/loading/selected ветки по применимости, темы и взаимодействия.

Существующие Label/Inline Message вставляются как компоненты со своей семантикой. Роли тела нового поля создаются отдельно; родитель не подменяет токены вложенных компонентов.

Локальный parse/проверка props-node, визуальный паритет и фактическая публикация — разные проверки. SVG-import не доказывает редактируемый DS-компонент с Variables. Внешняя запись выполняется в пределах поручения; отсутствие разрешения не останавливает независимую локальную работу, но ограничивает поставку.

Использовать обязательные навыки подключённого Figma-плагина, когда задача требует соответствующего инструмента. Результаты и ревизии — в Verification одного Spec. [Качество](quality.md).
