# Владение и полномочия

Владелец определяет назначение, существенные визуальные/API-решения, исключения и приёмку. Ясные рутинные действия в согласованном scope выполняются самостоятельно; ранее данные полномочия сохраняются между чатами.

Изменение общего процесса — отдельная порученная работа среды. Обычная компонентная задача не переписывает общие правила. Аудит не разрешает скрытый ремонт.

Сохранять чужие/прежние изменения и Git историю. Работать в отдельной ветке, без прямого изменения main и обхода review/защиты. Commit/push/PR/publish, изменение Secrets/доступов и глобальной конфигурации клиента выполняются только в соответствующих полномочиях.

Внешняя запись в Figma в порученной задаче не требует повторного формального вопроса, если уже разрешена. Новый выход за scope требует конкретного подготовленного действия и объяснения основания. Roadmap/скилл не предоставляют полномочия сами по себе.

Секреты не включаются в Git, журналы или evidence. Независимая библиотека не требует приватной среды разработчика для работы. Интеграции иконок/графиков исключены до нового явного поручения.

Описание read-only роли не является технической песочницей: права задаёт клиент/sandbox. Нативное подключение, доступность моделей/инструментов и результат реального запуска проверяются отдельно от описания.
