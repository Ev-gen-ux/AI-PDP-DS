# Токены и темы

У каждой системы собственные источники tokens, генератор, темы и связь с Figma. Компоненты используют семантические роли, палитра служит основой их построения. Имена отражают принятую архитектуру конкретной системы; похожее имя не доказывает совпадения resolved value.

Цветовая семантика компонентная: сначала роли тела компонента, затем их привязки и синхронизация кода. Вложенный DS-компонент сохраняет свои токены. Пример структуры — element/role/property/state; разделители Figma/JS/CSS согласуются генератором. Числа/шкалы соседней системы не копируются автоматически.

Изменение проходит цепочку: источник и решение → JSON/Variables → генерация → diff → потребители и темы. Проверять alias-ссылки, циклы, типы и фактические значения. Опечатка исправляется в источнике; временный alias в компоненте не скрывает дефект.

Не править generated TS/CSS руками и не ослаблять тип темы. Наличие $type/$value не доказывает соответствие всему DTCG. Изменение формата/генератора требует отдельной проверки. Shadow/effect styles не объявляются поддержанными Variables без реального механизма.

При общем токене определить влияние на семантику, компоненты и stories. Каталог точных ссылок отличается от динамических кандидатов и не является полным графом импортов. Применить [проверки](quality.md) и собственный профиль выбранного проекта.
