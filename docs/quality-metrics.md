| Пробел                                                                                  | Рекомендация                                                                                                                                                                       |

| **Тестовое покрытие success**         | Нет отдельного теста на класс/стиль рамки при `success` (только косвенно через stories)           | Опционально: data-attribute или snapshot темы — по политике библиотеки                  |

#### Что было непонятно или двусмысленно

| Зона                                                 | Неоднозначность                                                                                  | Как снять                                                                                              |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------ |
| **Success без автоправила**                          | Макет связывает success с «value»; в коде success только от пропа, без автопроверки строки email | Контракт: родитель выставляет **`success`** после своей валидации (или оставить так и описать в спеке) |
| **Размер иконки clear 16px vs обводка 24px в Figma** | В макете справа иконка в контейнере 24px; в коде кнопка 16×16 как у InputSearch                  | При расхождении с пиксель-пёрфект — сверить master-node и выровнять hit-area (§9 touch target)         |

**Интерпретация:** **`InputEmail`** собран по тому же архитектурному шаблону, что **`InputSearch`** (ведущая иконка, clear, `inputEmail.*` для поля), с полным набором **собственных** токенов рамки (в отличие от гибрида `input` + `inputSearch`). Основные уроки сессии — **документировать проп `success`**, проверить **hover vs success** и **фон error** против финального Figma, закрыть **формальные gates** (spec, visual parity, Code Connect).
