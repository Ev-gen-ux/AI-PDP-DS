# AI-PDP-DS

**От макета к проверяемому компоненту: Figma, дизайн-токены, React и правила работы с AI.**

AI-PDP-DS — открытая дизайн-система в активной разработке. Она объединяет визуальные решения в Figma, семантические токены, типизированные компоненты и процесс проверки изменений. Этот Storybook — интерактивная витрина реализованной части библиотеки.

[Полное описание и запуск на GitHub](https://github.com/Ev-gen-ux/AI-PDP-DS#readme) · [Figma](https://www.figma.com/design/i7T3ru2M0SyXgJeTda8f43/AI-PDP-DS) · [Issues](https://github.com/Ev-gen-ux/AI-PDP-DS/issues)

## Зачем нужна система

Макет, код и документация могут расходиться: компоненты получают разные отступы, состояния теряются, а AI-агент заполняет пробелы собственными предположениями. Проект задаёт общий процесс: описать варианты, связать значения с токенами, реализовать поведение и проверить результат.

Дизайнер может проследить связь макета и реализации, разработчик — изучить API и состояния, а команда — использовать структуру проекта как основу для развития своей библиотеки. Посетителю портфолио достаточно браузера, чтобы увидеть работающие компоненты.

## Что посмотреть

- **Components** — кнопки, поля, элементы выбора, навигация, уведомления, модальные окна, табличные примитивы и другие элементы интерфейса.
- **Layouts** — Stack, Cluster и Grid для компоновки компонентов.
- **Foundation/ThemeCheck** — собранные примеры для просмотра светлой и тёмной тем.
- **Foundation** — отдельные страницы палитры, примитивов, семантических цветов, типографики, отступов, радиусов и теней. Overview объясняет устройство токенов; Token Reference позволяет найти значение и ссылки на использование в реализации. Динамические ссылки обозначены отдельно от прямых.
- **Docs** внутри компонента — описание, доступные свойства и примеры.

Откройте **Default**, где он предусмотрен, и меняйте свойства через **Controls**. Затем проверьте клики, наведение и фокус с клавиатуры. Демонстрационные stories помогают сравнивать варианты, disabled, loading и статусы полей там, где такие состояния поддерживаются.

## Темы и адаптивность

Переключатель **Theme** в панели инструментов меняет светлую и тёмную тему. Цвета, отступы, радиусы и типографика заданы токенами; компоненты используют значения с назначением, например фон кнопки в состоянии hover.

Типографика предусматривает режимы XL, MD и XS. Изменяйте ширину окна или доступный viewport, чтобы исследовать поведение примеров. Полная проверка адаптивности и доступности требует просмотра конкретных сценариев; наличие story не подтверждает автоматически их полноту.

## Как связаны дизайн и код

Мастер-компонент Figma задаёт визуальные требования. JSON-токены в репозитории позволяют собрать тему без подключения к Figma. Style Dictionary генерирует CSS-переменные и TypeScript-объект темы, а React-компоненты используют их через styled-components.

В проекте есть получение токенов из Figma и обратная отправка с предварительным планом изменений. Для Button подготовлен, протестирован и опубликован через CLI шаблон Code Connect; остальные связи развиваются отдельно. Эти интеграции зависят от плана и прав Figma: публикация библиотеки сама по себе не даёт доступ к Code Connect и Variables API.

## Контракт разработки с AI

В [CLAUDE.md](https://github.com/Ev-gen-ux/AI-PDP-DS/blob/main/CLAUDE.md) закреплены правила: перед реализацией определить источник в Figma, варианты, точные значения и токены состояний; затем проверить код, stories и соответствие макету.

AI участвует в реализации по этому контракту. Часть требований проверяется инструментами, часть требует сверки с Figma и review. Контракт описывает ожидаемый процесс, а не заменяет контроль качества результата.

## Как выявляются ошибки

TypeScript проверяет типы, ESLint и Prettier — код и форматирование, Vitest — описанные сценарии поведения. Storybook помогает исследовать компонент вручную, addon-a11y — находить часть проблем доступности. Chromatic сравнивает визуальные снимки stories.

В текущей настройке визуальные изменения Chromatic не блокируют CI, а baseline в `main` принимается автоматически. Результаты проверок и разборы инцидентов записываются в [метрики качества](https://github.com/Ev-gen-ux/AI-PDP-DS/blob/main/docs/quality-metrics.md). Команда `quality:report` собирает результаты проверок и покрытие; GitHub Actions сохраняет Summary, JSON и журналы. Отдельный аналитический кабинет в текущий сценарий не входит.

Если нашли ошибку, укажите компонент и story, тему, ширину экрана, действия, ожидаемый и фактический результат в [Issue](https://github.com/Ev-gen-ux/AI-PDP-DS/issues).

## Локальный запуск

Используйте Node.js согласно `.nvmrc` и npm от 10:

```bash
git clone https://github.com/Ev-gen-ux/AI-PDP-DS.git
cd AI-PDP-DS
nvm use
npm ci
npm run tokens:build
npm run storybook
```

Локальный адрес — **http://localhost:6006**. Для просмотра компонентов из сохранённых исходников токены Figma и Chromatic не нужны.

## Как подключаются компоненты

```bash
npm install @evgeni_design_84/ai-pdp-ds react react-dom styled-components
```

При работе с исходниками нужны React, styled-components, объект `theme` в `ThemeProvider`, CSS-переменные обеих тем и шрифты. Цветовая тема выбирается атрибутом `data-theme`. Один `ThemeProvider` без CSS не задаёт значения переменных.

Инструкция установки через npm или архив, подключения компонентов и настройки собственного fork приведена в [README](https://github.com/Ev-gen-ux/AI-PDP-DS#подключение-к-приложению). В приложении достаточно импортировать `theme/variables.css`: он включает обе темы и шрифты.

## Обновления

Публичный Storybook обновляется после слияния изменений в `main` и успешного запуска публикации в Chromatic. Исходный код, спецификации и правила процесса доступны в репозитории.
