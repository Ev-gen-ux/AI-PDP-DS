# Результат P0.3

Дата завершения локальной реализации: 25 ноября 2026 года. Основание: [принятое решение 001](decisions/001-environment-architecture.md).

## Что введено

- Корневой [AGENTS.md](../../AGENTS.md) — общий контракт и обязательная маршрутизация.
- Десять стандартов в standards/, семь индексов подсред в domains/, onboarding и процедура компонентной задачи.
- CLAUDE.md и cursor_instruction.md — короткие входы к одному нормативному ядру.
- Шаблоны Spec/PR согласованы с D1/D2/D4; AllVariants больше не универсальное требование.
- Четыре прежних документа сохранены в неактивном архиве references/. Они не подключаются как обязательные инструкции.
- [Реестр переноса](migration-ledger.json) покрывает все 959 ID из [исходной карты](../environment-rule-map.json). Он описывает назначения, объединения и архивирование; текстовое покрытие не заменяет смысловой review.
- README и Introduction направляют к новому входу; исторические аудиты явно отделены от текущего контракта.

## Проверка переноса

Проверены уникальность и полнота 959 назначений, существование целевых файлов, SHA-256 шести исходников на f53590c, точное сохранение исходного текста четырёх архивов и их SHA-256 в references/legacy-sources.json (читаемая Markdown-копия Cursor нормализует завершающие пробелы строки версии), локальные ссылки активных документов и односторонний импорт CLAUDE → AGENTS. Исходная карта не переписывается после смены контракта: она сохраняет утверждённую базу инвентаризации.

Смысловой review групп требований выполнен по стандартам. Существенные изменения связаны с D1–D10; реализация открытых технических вопросов отделена от нормативного переноса. При этом реестр не является автоматическим доказательством эквивалентности каждой формулировки.

Ручной проход маршрутов по текстам:

| Сценарий                   | Проверенный маршрут и ограничение                                                                                       |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| Невизуальный багфикс       | tasks → components → quality; существующий Spec и регрессионная проверка, без полного нового визуального брифа          |
| Новый визуальный компонент | Полный Spec и матрицы; нет обязательных значений Figma — зависимая реализация блокируется, пока не принят иной источник |
| Code-first                 | Источник и приёмка явно согласованы; режим не включается автоматически при отсутствии Figma                             |
| Аудит                      | Findings/evidence, без незаказанной реализации                                                                          |
| Иконка                     | Icon-слой и 16/24 сохранены; meta/CodeIcon расхождение остаётся отдельным вопросом                                      |
| Документация               | Scope и релевантные проверки; полный компонентный Spec не требуется без изменения компонента                            |

Это review маршрутов инструкций, не экспериментальное выполнение задач разными агентскими клиентами. Реальное обнаружение навыков, hooks и поведение клиентов проверяются последующими этапами.

## Автоматические проверки

[Отчёт локального прогона](P03-quality-2026-11-25.json): 10/10 PASS на Node 22.17.0, 175/175 тестов. Проверены генерация токенов, typecheck, lint, формат, coverage/tooling tests, сборки библиотеки и Storybook, потребитель пакета и Code Connect parse. Прогон относится к f53590c с локальными изменениями P0.3; итоговое оформление документов проверено отдельно. Это не проверка поведения всех агентских клиентов или ручного визуального соответствия.

## Следующие этапы

P0.4: минимальное состояние задачи, ссылки на Spec и ревизии, проверяемая инициализация и возобновление. P0.5: навыки. P1.1: постоянные проверки самой среды и CI. Новые task validators, skills и генератор компонентного индекса в P0.3 не устанавливались.

Отдельно остаются согласование точного runtime-профиля Node 22 и синхронизация конфигураций, решение об изменении fallback, лицензирование и пилоты модулей. Исходники компонентов, токены, зависимости и workflows публикации сохранены. Старую рабочую папку и резервный тег см. в [подготовке](../environment-preparation.md).
