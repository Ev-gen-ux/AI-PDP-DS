# Совместимость, PR и выпуск

Работать в отдельной ветке от актуального main: feat/, fix/, chore/, tokens/ по задаче. Коммиты Conventional Commits: feat, fix, chore, docs, refactor, test, tokens. Прямой push в main и обход review запрещены; объединение через PR.

Перед PR явно определить влияние:

- новый компонент/расширение API или поведения требует changeset; patch — совместимый багфикс, minor — совместимое расширение, major — несовместимое удаление/переименование/поведение;
- внутренняя правка или документация без влияния на API может не иметь changeset, в PR указать No public API impact;
- для глобального релиза changesets соответствуют фактическим изменениям.

Отсутствие нужной записи версии — VERSIONING VIOLATION с указанием требуемого исправления. Версия относится к библиотеке; изменения компонентов описываются внутри её changelog. Совместимость оценивает также публичные CSS-роли, семантику и layout, не только TypeScript.

Имя пакета в changeset читать из package.json (сейчас @evgeni_design_84/ai-pdp-ds). Не копировать старое имя из архива. Release note содержит Component, Change type, User impact, Migration и Verification.

PR описывает что изменено, почему, как проверено и риски/совместимость; для компонента применимы Spec, ThemeCheck, Code Connect и визуальные доказательства. Перед выпуском пройти format:check, typecheck, lint, test и предусмотренные CI-проверки. Все согласованные changesets актуальны.

Публикация библиотеки, Storybook или запись во внешнюю библиотеку выполняются только в пределах явного поручения и ранее предоставленных полномочий. Наличие навыка/workflow само разрешение не расширяет. Факт публикации проверяется отдельно; согласование переноса инструкций не является поручением выпустить npm-релиз.
