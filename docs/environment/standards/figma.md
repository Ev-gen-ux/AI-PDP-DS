# Figma, числовые значения и соответствие

Для существующего визуального контракта приоритет у текущего Figma master и согласованного Spec. Предыдущий код и соседний компонент не заменяют источник. Для code-first задачи заранее согласовать Spec, допустимый источник чисел и визуальную приёмку; отсутствие доступа к Figma не разрешает угадывать значения.

## До визуальной реализации

Для каждого применимого варианта выписать padding T/R/B/L, gap, radius, font-size, line-height и карту источник → токен → resolved value. При Figma-first числа берутся из конкретного master-node без усреднения. Radius проверяется отдельно для каждого размера; подходящее имя токена не компенсирует несовпадение значения. Числа и источник зафиксировать в kickoff/Spec и сообщить до стилевых maps.

Нужна State Token Matrix для всех применимых appearance/state/selected/loading: background, border, label, icon, padding, height, radius. Для разных цветовых ролей label и icon нужны отдельные карты состояний. Hard Constraints сохраняют размеры, заливки и неизменяемые правила. Недоступное обязательное значение или конфликт фиксируются как блокер зависимого изменения.

Матрицы обновляются до реализации нового варианта. Строковые имена Figma-вариантов сохраняются в mapping 1:1.

## Проверка результата

Отдельно сверить enabled, hover, active, focus, disabled, loading и selected-ветки для каждой применимой appearance по Spec. Проверка включает реальное взаимодействие в Storybook и сравнение с master; принудительные demo-состояния не должны блокировать настоящие псевдоклассы Default story.

Для нового/изменённого .figma.tsx проверить точное соответствие props/enum/node и публикацию в рамках уже разрешённой поставки: figma:publish либо соответствующий CI-run, затем фактический результат. Если публикация не разрешена/недоступна, локальную работу продолжать в независимой части, а зависимую поставку не объявлять завершённой.

figma:check проверяет parse/дубликаты, не подтверждает публикацию или визуальный паритет. Импорт SVG не доказывает редактируемый Figma-компонент с правильной анатомией и variables. Все результаты заносить в Verification единого Spec с ревизиями.
