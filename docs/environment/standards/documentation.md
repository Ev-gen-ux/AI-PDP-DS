# Документация и Storybook

Документация соответствует реальным API, состояниям и ограничениям реализации. Генерируемые факты берутся из кода/токенов; принятые решения сохраняются в Component Spec. Фактический каталог строится из exports/stories, а зрелость и визуальная приёмка подтверждаются отдельно. Игнорируемый component_list.md не является доступным каждому checkout источником статусов.

## Stories

1. tags: ['autodocs']; краткое описание компонента в parameters.docs.description.component.
2. Описания ключевых props в argTypes; описания story, когда нужно пояснить сценарий.
3. Первая story — Default: один интерактивный компонент, controls не блокируют реальные hover/active/focus-visible.
4. Далее отдельные stories по appearance/вариантам; применимые состояния внутри appearance-story вертикальным списком. AllVariants не обязателен.
5. Демонстрационные принудительные состояния размещаются отдельно от Default. Для интерактивного компонента покрыть default, hover, focus, disabled, применимые loading/error/success и каждую appearance.
6. Stories соответствуют только размерам master/принятого Spec; новые размеры требуют изменения Spec.
7. Стандартный decorator примера задаёт padding 24px. Для фиксированного примера поля: внешние отступы 24px 0 24px 24px и ширина 320px; эти демонстрационные значения не являются токенами реализации компонента. Не растягивать компонент без основания; использовать alignItems: flex-start либо нужную фиксированную ширину. Не задавать docs.story.height, если это создаёт ненужный внутренний scroll.
8. Не добавлять заголовки состояний над экземплярами, когда состояние считывается из самого компонента.
9. Алфавитная стабильная сортировка через storySort method alphabetical, locales en-US. Иерархия Components/Name, Foundation/Name, Icons/Name; искусственные числовые префиксы запрещены.

При добавлении компонента или изменении интерактивного поведения обновить Foundation/ThemeCheck: применимые appearance, selected/unselected, loading/disabled. Отсутствие синхронизации делает задачу неполной.

Поддерживать Foundations на существующей генерации; не создавать второй ручной источник токенов. Storybook build проверяет сборку; interaction, visual и accessibility результаты фиксируются отдельно. Подключение AI manifest/MCP более новой версии требует отдельного пилота, не скрытого upgrade.
