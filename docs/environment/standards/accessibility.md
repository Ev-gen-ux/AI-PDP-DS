# Доступность и адаптивность

Все применимые требования обязательны для интерактивных компонентов.

- Видимый :focus-visible через theme.colors.focus.ring.default. Единый ring: 0px 0px 0px 2px с цветом токена. Для кнопки — focus-visible, для поля — соответствующее состояние контейнера. Не удваивать outline и box-shadow.
- Button по умолчанию type="button"; toggle использует aria-pressed.
- Loading отражается aria-busy и блокирует мышь и клавиатуру нативным disabled либо описанным строгим эквивалентом. pointer-events: none недостаточно.
- aria-disabled при сохранении фокуса требует описанного сценария, например tooltip, и управления фокусом.
- Ошибка поля: aria-invalid и aria-describedby.
- Modal/Drawer: focus trap, Esc, aria-labelledby и aria-describedby.
- Tabs/Accordion: клавиатура со стрелками, Home, End по применимому паттерну.
- WCAG AA: 4.5:1 обычный текст, 3:1 крупный текст и интерактивные границы.
- Мобильный touch target не меньше 44×44px.

Адаптация mobile-first через theme.breakpoints; текущие xs=480, md=768, xl=1280 сверяются с источниками. Типографика XS/MD/XL использует CSS variables, не JS-перерисовку для каждого размера. Для содержательных компонентов в разных колонках нужны container queries. Проверять overflow, reflow, zoom, размер контейнера и контент.

Для композиции использовать существующие Stack/Cluster/Grid и другие реально доступные layout-примитивы. Не считать запланированный Sidebar layout готовым из-за наличия одноимённого UI-компонента. Экран — типизированный React-компонент; JSON-композиции экранов не вводятся.

Проверять реальные клавиатурные сценарии, фокус, assistive technology и применимые темы. Автоматические тесты и axe-проверки используются там, где настроены; их PASS не доказывает полную доступность. Недоступную ручную проверку указывать явно.
