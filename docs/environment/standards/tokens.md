# Требования к токенам и темам

Источник визуальных токенов — согласованный Figma-файл и принятый процесс синхронизации; воспроизводимые данные библиотеки хранятся в tokens/. Изменения должны согласовывать оба представления, а не маскировать расхождение в компоненте.

## Именование и применение

Структура имён зеркалит Figma: / в Figma, . в JS, - в CSS. Цвета используют element/role/property/state, например button/primary/background/enabled. Палитра neutral, blue, green, red, yellow, cyan, pink и base/white служит источником генерации семантики; компоненты используют только семантические роли.

Spacing:

- inner — внутри компонента и между связанными элементами;
- outer — между компонентами/секциями;
- paddings — padding контейнера;
- height — фиксированная высота;
- grid — параметры сетки.

Radius выбирается по уровню вложенности: componentInner, componentBase, sectionInner, containerBase, sectionBase и rounded. Значения читать из исходников/темы, а не копировать исторические числа в стили.

Типографика: fontSize, lineHeight и fontWeight с ролями heading/text/component и согласованной шкалой. Цвета имеют light/dark modes, типографика XL/MD/XS; spacing и radius едины между режимами. ThemeProvider переключает темы, CSS variables и media queries обеспечивают адаптивную типографику.

## Изменения

Если значения нет, не вводить хардкод. Согласовать изменение исходника токена с владельцем, обновить JSON и выполнить tokens:build; сравнить generation diff, зависимые компоненты и Foundations. Проверять фактическое resolved value, а не выбирать токен только по похожему имени.

При опечатках/неверных значениях сначала исправлять источник Figma, затем pull/sync и diff в tokens/. Не вводить временный alias для ошибочного имени в компонентах. Исторические случаи — справочный материал, а не доказательство текущего дефекта.

Не редактировать производные src/theme/tokens.ts и CSS вручную. Тип темы остаётся строгим. Полное соответствие актуальному DTCG формату не следует из одного наличия $type/$value: изменение формата требует отдельной проверки схем и генератора.
