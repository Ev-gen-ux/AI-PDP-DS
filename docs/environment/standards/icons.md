# Требования к иконографии

Продуктовые иконки подключаются через библиотечный слой src/components/icon (alias @/components/icon). Прямой импорт Phosphor в потребляющий компонент запрещён. Новую иконку сначала добавлять в Icon-слой.

Текущий публичный IconSize — 16 | 24. Для каждого размера компонента нужен явный componentSize → iconSize map, зафиксированный в коде, Spec и story; не выбирать размер эвристически. Ориентир legacy-контракта: 48px → 24px, 32px → 16px; реальные размеры источника проверяются отдельно. Не вводить 20px из устаревшего примера.

Не создавать SVG-path внутри компонента как замену продуктовой иконке. Авторские SVG допустимы в отдельно порученной задаче иконографии с согласованным профилем и приёмкой.

Если смысл иконки не определён, действующее требование — временный meta fallback с явной записью в задаче/PR. Размер или смысл уточняются до зависимого решения; временный map требует согласования. В реализации fallbackIconGlyph пока указывает на CodeIcon, отдельно экспортируется metaIconGlyph. Это открытое расхождение, а не новый стандарт; исправление поведения — отдельная задача.

Перед завершением потребителя проверить источник, fallback, семантический смысл и map размеров. Для собственных наборов сохранять паспорт, эталоны, исходный редактируемый SVG и происхождение производного экспорта. Проверять viewBox/масштабирование, цвета/currentColor по профилю, отсутствие случайного растра и обрезания. Технический SVG-аудит не заменяет визуальную проверку узнаваемости, веса и согласованности набора. Ручные принятые изменения не перезаписывать старой генерацией.

Подключение custom-icons и внешних генераторов выполняется отдельным этапом с версией, лицензией, бюджетом при необходимости и проверкой текущего Icon API.
