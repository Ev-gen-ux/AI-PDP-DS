# Навыки и рабочие директивы

P0.5: девять канонических навыков в `.agents/skills/`. Навык описывает назначение и выбирает процедуру; исполняемый порядок находится в workflows/, требования — в standards/. Применимость стандартов задаёт [AGENTS.md](../../AGENTS.md), независимо от выбора навыка.

## Смешанные задачи и границы

- Намерение определяет действие: «проверь Button» выбирает аудит, даже если виден дефект; «исправь и проверь» — ремонт с проверкой. Для чистого Figma-сравнения применим parity; это тоже маршрут без незаказанного исправления.
- Ясный компонентный запрос сразу идёт в предметную процедуру. Intake подключается для неизвестных, исследование — для реальной неопределённости/явного поручения. Не превращать девять навыков в девять обязательных этапов.
- Новый вариант — компонентный контракт; мелкий ремонт реализации остаётся repair. Изменение существующего токена в рамках задачи добавляет tokens-процедуру; использование уже существующего токена не запускает миграцию.
- Для смешанной поставки объединить применимые предметные стандарты, сохранив один scope/Spec и ссылки на результаты. Если часть поручения только аудит, её источники не менять. Документация и проверка являются частью соответствующей реализации и не требуют отдельного повторного брифа.
- Публикация имеет явный вход по запросу; автоматический выбор ds-release не расширяет полномочия. Подготовка/commit/push/merge/deploy имеют разные границы по поручению. Отсутствие инструмента не разрешает подменить результат.
- Для иконок и графиков использовать [icons](domains/icons.md)/[charts](domains/charts.md). Специализированные разработчики, генераторы и runtime из WorkEnvironment ещё не подключены; наличие маршрута не делает их установленными.

## Размещение и совместимость

Каждый навык имеет один SKILL.md с name/description и относительными ссылками, разрешаемыми от его каталога. Команды выполняются из корня выбранной Git-рабочей копии. Глобальные каталоги и настройки клиента не изменяются. Прямое чтение SKILL.md и workflow доступно независимо от автоматического обнаружения.

В этой поставке проверяются структура, ссылки и ручной разбор маршрутов. Автоматическое обнаружение в новой сессии Codex, invocation/reading scopes, адаптеры Claude/Cursor и поведение на одинаковых задачах проверяются в P1.2. В текущую сессию новые навыки автоматически не объявляются загруженными. Дубликаты в .claude/.cursor не создаются. Механические CI-проверки среды входят в P1.1.
