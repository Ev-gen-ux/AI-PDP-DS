## Что подтверждено локально сейчас

- В исходниках InputSearch/InputEmail mapping остаётся placeholder; отдельные component-spec файлы с ожидаемыми именами отсутствуют. Это ограниченное файловое наблюдение, не утверждение, что все принятые требования потеряны или текущее поведение ошибочно. В P1.1 компоненты не исправляются.
- Существующий check-code-connect проверяет распознанные шаблоны/дубликаты, но не полноту покрытия всех компонентов и не публикацию. Сохранённый локальный parse на базе P0.5 содержит один шаблон Button. Полное покрытие и внешняя приёмка остаются отдельной задачей.
- Divider содержит min-height для vertical, InputDate учитывает фокус при показе overlay; это подтверждает наличие исторических исправлений, но не актуальный визуальный паритет.
- В runtime состояния задачи уже есть запрет ready для component без Spec и accepted без актуальной приёмки/проверок. Новая диагностика вызывает тот же валидатор только для явно выбранной локальной задачи. Одна успешная декларация evidence сама не доказывает реальное выполнение проверки.

## Поставка P1.1

[Диагностика](workflows/environment-checks.md) проверяет пути, обязательные ссылки, метаданные, совместимость декларативных маршрутов, целостность всех 959 записей переноса и архивов. Отрицательные fixtures проверяют неверную маршрутизацию, пропущенный стандарт, повреждение входов и ложную согласованность task state. Существующие тесты P0.4 продолжают проверять повторный init, ручные изменения, history/CAS и stale приёмку.

Новые обязательные продуктовые правила из единичных исторических случаев не вводятся. Сам журнал не превращается во второй контракт. Полное исследование Figma, исправление названных компонентов и browser/client behavioral evaluation не выполнялись; соответствующие задачи сохраняют собственный scope и критерии приёмки.
