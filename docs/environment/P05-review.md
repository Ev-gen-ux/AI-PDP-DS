# P0.5: разбор маршрутов

Дата: 25 ноября 2026 года. Метод — ручное чтение девяти SKILL.md и связанных директив на контрольных запросах. Это проверка согласованности инструкций, не независимый запуск другой модели и не подтверждение автоматического выбора навыка клиентом.

| Контрольный запрос                                     | Маршрут и ожидаемая граница                                          | Результат чтения                                                                                   |
| ------------------------------------------------------ | -------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| «Нужен необычный выбор периода, пока не знаю какой»    | Intake → research при неопределённости; существенное решение до кода | Маршрут и выход определены; произвольный компонент не объявляется согласованным                    |
| «Создай компонент по принятому Spec и master»          | Create → component/new; общие вход/проверка                          | Новый общий бриф не требуется; Spec и применимые стандарты подключаются                            |
| «Добавь согласованный вариант существующего Button»    | Create/new variant с обновлением одного Spec                         | Не маскируется локальным ремонтом                                                                  |
| «Исправь повторный вызов обработчика, визуал не меняй» | Repair → причина → релевантная регрессия                             | Без полного визуального опроса; сохранение соседнего API                                           |
| «Проверь Button и перечисли проблемы»                  | Quality audit; код без исправления                                   | Команды с регенерацией требуют отдельной безопасной рабочей области; не запускается format --write |
| «Исправь Button и проверь результат»                   | Repair + verify-deliver                                              | Проверка не переводит порученную реализацию в read-only аудит                                      |
| «Поменяй значение семантического токена»               | Tokens, исходник → генерация → темы/потребители                      | Не редактируются производные; неизвестное новое значение уточняется                                |
| «Используй готовый токен вместо хардкода в компоненте» | Repair + tokens-стандарт                                             | Отдельная миграция всех токенов не требуется                                                       |
| «Сверь mapping с Figma, но доступа сейчас нет»         | Parity; локальная проверка и внешний блокер                          | Parse не выдаётся за визуальный паритет; значения не выдумываются                                  |
| «Обнови описание свойства в Storybook»                 | Documentation, сверка кода/Spec                                      | Без редизайна компонента и автоматического деплоя                                                  |
| «Продолжи принятую задачу после новой сессии»          | Task-start → resume → stale/diff → прежний маршрут                   | Нет повторного init и брифа; refresh не подтверждает старые evidence                               |
| «Подготовь выпуск, пока не публикуй»                   | Release/preparation                                                  | Обозримый пакет изменений без публикации; уже данные полномочия учитываются                        |
| «Сделай аудит иконок, рисунки не меняй»                | Quality audit + icons-индекс                                         | Новый разработчик иконок/генератор не запускается                                                  |
| «Начни разработку графиков»                            | Charts-индекс; выяснить scope последующего пилота                    | P0.5 не заявляет готовый chart-runtime или доступ к приватному модулю                              |

При чтении устранено безусловное открытие PR из старого component workflow: общая передача теперь связывает commit/push/PR с поручением и ранее данными полномочиями. Аудит отдельно учитывает побочные эффекты quality:report. Ручной разбор не доказывает соблюдение этих границ инструментом: права остаются в клиенте/sandbox.

## Референс

Локальная копия WorkEnvironment: ревизия `1a4ed91c32d0db104fed68c4ef7816ef0aea079a`. Просмотрены корневые CLAUDE/PROCESS, вход custom-icons, SKILL.md и workflow подсред icons/charts. Использован принцип разделения роли/маршрута, исполняемых директив и справки. Файлы приватного модуля, инструменты и активы не копировались; runtime-зависимость не добавлена. Источник — [WorkEnvironment](https://github.com/Ev-gen-ux/work-environment).

## Отдельные последующие проверки

P1.1 — независимые от AI-клиента проверки метаданных, ссылок, маршрутов и отрицательных fixtures в CI. P1.2 — фактическое обнаружение/вызов из корня и подпапки, Codex и другие адаптеры, одинаковые задания и независимые наблюдения поведения. Эти результаты пока не заявлены. Обычный format/typecheck/test не заменяет их.
