# Документация и примеры

После [входа](task-start.md) открыть [индекс documentation](../domains/documentation.md); для описываемого API/токенов прочитать соответствующий предметный индекс. Определить аудиторию и затронутые документы/примеры по фактическому изменению.

Сверить props, экспорты, defaults, ограничения и состояния с кодом и принятым Spec. Если они конфликтуют, указать конфликт и описать фактическое поведение отдельно от требования; не переделывать компонент под документацию без задачи. Искать существующее место описания и обновлять его, сохраняя один источник факта.

Для Storybook применять стандарт документации, проверить компиляцию и затронутый интерактивный пример; сборку не объявлять визуальной/interaction-проверкой. Для Foundations опираться на существующую генерацию, а не ручной второй каталог. Проверить ссылки, примеры подключения и имя/версии пакета по исходникам. При миграции объяснить изменение потребителю и необходимые действия.

Выход: актуальные описания и примеры, источник подтверждения API, результат проверок и известные ограничения. Завершить по [передаче](verify-deliver.md); документационная задача не запускает релиз/деплой автоматически.
