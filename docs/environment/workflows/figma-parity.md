# Figma: соответствие и mapping

После [входа](task-start.md) открыть [индекс figma](../domains/figma.md). Выбрать проверку соответствия, локальную правку mapping либо явно порученную внешнюю запись. Для сравнения только читать источники; найденное расхождение само не разрешает исправление.

Установить конкретный master-node и актуальную ревизию, единый Spec, реализацию, stories и файл Code Connect. Выписать сравнимые варианты/состояния, числовые значения и разрешённые токены по стандарту figma. Для доступного визуального сравнения проверить компонент в темах и взаимодействиях, а не только статичный Default.

При работе через Figma-инструменты сначала загрузить обязательные профильные навыки, доступные в текущем клиенте, и использовать фактическую схему tools. При отсутствии доступа выполнить независимый анализ локального Spec/mapping/кода; значения и визуальный паритет Figma оставить непроверенными. Code-first требует ранее согласованного источника и приёмки.

Для разрешённого изменения mapping сверить node, props, enum и строки вариантов 1:1, выполнить `npm run figma:check`. Публиковать только в разрешённой поставке, затем проверить фактический результат. Parse, публикация и визуальный паритет — разные записи.

Выход: таблица «источник/вариант → код/токен/mapping → совпадение или расхождение», evidence и ограничения; при порученной правке также diff и её проверки. Завершить по [передаче](verify-deliver.md); исправление компонента передать компонентному маршруту в пределах полномочий.
