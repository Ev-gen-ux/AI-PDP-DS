# Подготовка и разрешённая публикация

Вход — явный запрос на выпуск/подготовку выпуска. После [начала задачи](task-start.md) прочитать [releases](../standards/releases.md) и [governance](../standards/governance.md). Установить продукт поставки: npm-библиотека, Storybook, Code Connect либо только материалы review. Запрос подготовить выпуск разрешает подготовку; публикация требует своих полномочий, с учётом уже данных владельцем.

1. Проверить состав diff и зависимостей, фактические имя/версию пакета, согласованные Spec/changesets, совместимость и миграцию. Не брать версию или зрелость компонента из исторической документации.
2. Подготовить changeset при публичном влиянии, заметки и PR по стандарту; проверить содержимое пакета и необходимые команды качества. Подготовку локальных артефактов довести до обозримого результата до запроса ещё отсутствующего разрешения на внешний шаг.
3. Перед внешней записью сверить точный артефакт/ревизию, назначение, необходимые review/CI и действующий workflow. Не менять защиту ветки, secrets и настройки доступов ради обхода. Не объединять main как побочный эффект подготовки.
4. При разрешённой публикации использовать существующий процесс; проверить результат в целевой системе: имя, версия/канал, ревизия, URL или подтверждение сервиса. Если ответ неоднозначен/сеть оборвалась, сначала выяснить фактический статус, не повторять публикацию вслепую и не переиздавать версию. При отсутствии доступа завершить доступную подготовку, внешний шаг отметить как не выполненный.

Выход: состав и влияние, changeset/notes при необходимости, доказательства проверок и отдельный фактический статус публикации. Пройти [передачу](verify-deliver.md). Наличие этого workflow не вводит автоматический push/deploy для обычных задач.
