# Уточнение задачи

После [входа](task-start.md) собрать известные сведения из запроса, кода, Spec и решений. Для короткой ясной правки сразу передать задачу предметной процедуре, без обязательного интервью.

Для размытого запроса выяснить только то, что меняет решение: пользовательский сценарий и желаемое поведение, существующий объект, источник дизайна, необходимые состояния, платформа и ожидаемая поставка. Не просить владельца самостоятельно написать ТЗ вместо уточнения агентом. Вопросы задавать небольшими связанными группами; глубина зависит от неопределённости.

Зафиксировать подтверждённое, предположения и вопросы отдельно. При конфликте Spec/Figma/кода показать конкретные варианты с последствиями до зависимого изменения. Не считать тишину согласием; независимую работу выполнять в уже известных границах.

Выход: краткая постановка со scope, источниками/ревизиями, критериями приёмки, существенными вопросами и выбранным следующим маршрутом. Для компонента решения разместить в едином Spec, для длительной задачи — ссылки в состоянии. Исследование назначить, если оно разрешает реальную неопределённость либо явно поручено. Завершить по [передаче результата](verify-deliver.md); уточнение не запускает реализацию несогласованного решения.
