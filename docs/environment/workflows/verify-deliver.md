# Проверка и передача результата

Общая рабочая директива завершения; команды и обязательные требования определяются [quality](../standards/quality.md), предметными стандартами и согласованными критериями задачи.

1. Сопоставить diff с scope и Spec, оценить совместимость и необходимые изменения документации/версии по [releases](../standards/releases.md). Для чистого аудита diff исходников должен оставаться неизменным; не запускать исправления ради зелёного результата.
2. Выбрать проверки по изменению и выполнить их на текущих входах. Сохранить метод, исходную ревизию/объявленные входы, дату, результат и существенные ограничения. Для полной проверки использовать существующий `quality:report`, а не новый параллельный механизм.
3. Разделить результаты технических тестов, ручного/визуального review, Figma-сопоставления и публикации. Недоступное/не выполненное отметить явно. Смена источников требует новой проверки; старое evidence не привязывать к новому fingerprint автоматически.
4. Обновить один Spec и состояние длительной задачи по [task-state](task-state.md). Сохранять историю; сохраняемый статус review означает готовность к рассмотрению, accepted требует реальной приёмки текущего результата. Если изменился Git HEAD после commit, проверить изменения, обновить ссылки и записать доказательства с точным происхождением.
5. Показать результат, проверки, ограничения и следующий шаг. Commit/push/PR выполнять, когда они входят в поручение или ранее предоставленные полномочия; сам вызов навыка не вводит обязательный автоматический push. Публикацию выполнять только по [процедуре выпуска](release.md) в разрешённых границах.

Окончание порученного исследования/аудита не означает реализацию рекомендаций. Если зависимая часть не завершена, назвать её конкретно; не объявлять весь компонент или среду готовыми по одному отчёту.
