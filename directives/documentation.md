# Документация

## Назначение и запуск

Использовать после [intake](intake.md) для создания/обновления документации системы или разработчика. Найти канонический документ до записи.

## Входы

Аудитория, цель, STATE, реальные API/команды/версии и принятые решения. Прочитать [стандарт документации](../docs/standards/documentation.md). Для директив использовать [общий формат](../templates/project-instructions.md#directive).

## Условия начала

Определены владелец документа и границы задачи. Исторический отчёт не становится текущим обещанием; данные проверить по фактическим исходникам.

## Этапы

1. Выбрать единственное место: общий Discovery, живой Component Spec, пользовательское docs либо инструкция разработчика.
2. Обновить содержание под актуальный контракт и аудиторию. Примеры используют публичные exports и поддерживаемые props.
3. Сохранить разделение: directives описывают действия/переходы, docs/standards — требования и справку, templates — формы, PROCESS — общий маршрут, config/routes.json — машинное соответствие.
4. Не размножать матрицы Spec в Storybook/журнале. В директиве связывать условные процедуры ссылками, не создавать второй процесс в справке.
5. Для изменения процедур обновить их callers, скиллы и реестр. Сохранить нужные предметные документы внутри проекта.

## Решения владельца

Существенное изменение правил процесса или продуктового контракта предъявить до зависимых действий. Редакторская правка в уже принятом scope не требует отдельного нового брифа.

## Результат

Актуальный канонический документ, согласованные ссылки/маршруты и подходящие пользовательские примеры без дублирующих источников.

## Проверка

Проверить локальные ссылки, формат и применимые примеры. Для среды выполнить [диагностику](environment-checks.md). Сборка Storybook не подтверждает интерактивное поведение примера. Закончить по [передаче](verify-deliver.md).

## Продолжение и возврат

Поправки вносятся в тот же документ; при изменении контракта вернуться к соответствующему Spec/процессу. Старую историю не выдавать за актуальную инструкцию и не создавать новый дублирующий журнал.
