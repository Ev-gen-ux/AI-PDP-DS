# Общий вход в задачу

## Назначение и запуск

Начинать из [AGENTS](../AGENTS.md) и [PROCESS](../PROCESS.md). Пользователь задаёт результат обычной фразой; ведущий выбирает контекст и процедуру. Keyword-подсказка env:route --request не заменяет понимание запроса.

## Входы

Текущее поручение, уже принятые решения, выбранная система и существующая задача/STATE, связанные Spec/источники. Маршруты и канонические файлы — [registry](../config/routes.json).

## Условия начала

До продуктовой записи однозначно выбрать систему и понять характер сообщения: новая задача, продолжение, замечание, приёмка, пауза или отмена. Указание только обсудить/исследовать ограничивает действия этим результатом.

## Этапы

1. Восстановить текущую задачу по контексту и журналу; не выбирать её по mtime. Продолжение не создаёт новый ID и не назначает приёмку молча.
2. Выбрать систему из контекста; при неоднозначности уточнить. env:project list показывает существующие системы. Нет скрытого выбора первой системы или режима «все».
3. Новую систему начать по [созданию](system.md). Для существующей все продуктовые материалы сразу находятся внутри неё; внешние workspace/intakes не создаются.
4. Новый компонент получает задачу через env:task init <task-id> --project <system-id> --component <component-id>. Для доработки/ремонта указать --action refine|repair. Первый Spec/brief/журнал находятся в component-specs/<component-id>; следующая отдельная задача — в его tasks/<task-id>, с тем же Spec. Исходники на этом шаге не генерируются.
5. Общесистемные задачи принадлежат product-discovery. Работа над самим разработчиком использует временную задачу --object environment по [STATE](task-state.md), без продуктовой копии в .local.
6. Выбрать скилл и нужного отдельного исполнителя по [координации](coordination.md). Пройти достаточное [брифование](briefing.md), затем предметную процедуру и только выбранную поставку.

## Решения владельца

Неоднозначный выбор системы, новый существенный контракт и изменение scope требуют решения владельца. Уже данные полномочия сохраняются. «Продолжай» не подменяет фактическую приёмку результата.

## Результат

Выбранные проект, задача, действие/объект и поставка; достаточные вводные или конкретные вопросы; однозначный следующий шаг в существующем STATE.

## Проверка

Для продолжения выполнить env:task resume <id> --project <system-id>, проверить scope, актуальность файлов/evidence и следующий шаг. Проверить, что кодовая ветка не требует Figma, а Figma-only не запускает ненужную кодовую среду.

## Продолжение и возврат

Замечание направить в текущую задачу и затронутую процедуру. Самостоятельный новый результат получает отдельную задачу. Иконки/графики исключены до нового явного поручения. Вызов директивы не разрешает публикацию или расширение scope.
