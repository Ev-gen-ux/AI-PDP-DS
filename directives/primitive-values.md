# Настройка примитивов проекта

## Назначение и запуск

Используется при первоначальной настройке системы и при последующей смене внешнего вида. Вход — [создание системы](system.md) либо [токены и темы](tokens-themes.md). Работать внутри выбранного projects/<id>.

## Входы

До настройки зафиксировать источник и версию фундамента: перечень токенов, типы, режимы, aliases и привязки компонентов. Код и Figma сопоставить по логическим ключам; одинаковое имя не доказывает одинаковый состав. Если источники расходятся, выбрать согласованный снимок и явно определить code-only/Figma-only параметры. Не приводить эталон к новой схеме попутно.

## Условия начала

В этом процессе меняются только разрешённые конечные значения примитивов. Имена семантики, типы, режимы, alias-цепочки, правила состояний и привязки компонентов сохраняются. Alias внутри примитивного слоя тоже остаётся alias. Вложенные Label/Inline Message сохраняют собственные роли; общий примитив может влиять на них через существующие связи.

Если заказчику нужен отсутствующий параметр, новый режим или независимая настройка связанных ролей, сначала сформулировать отдельное изменение фундамента. Не заменять alias литералом и не создавать обход в CSS ради прохождения этого шага.

## Этапы

### Матрица и данные заказчика

Форма согласования — [матрица](../templates/primitive-matrix.md). Фактические рабочие значения находятся только в tokens/primitives/. Матрица — представление этих данных и предлагаемого diff, не второй постоянно редактируемый источник.

Заказчик может дать текст, файл или ссылку. Ведущий извлекает данные доступными средствами и приводит к [машинному предложению](../templates/primitive-request.json). Автоматический парсер произвольных PDF/таблиц/текста не предполагается. Исходный материал и существенные пояснения сохраняются в product-discovery выбранного проекта; файлы заказчика в глобальную директиву не переносятся.

Для каждой строки показать ключ, тип/единицу, текущее и предлагаемое значение, источник, режимы/потребителей, связанность и решение. Неточное «основной цвет» сначала сопоставить существующему примитиву. Недостающие оттенки не выдумывать: явно оставить базовые значения либо предложить палитру для согласования.

Один примитив может управлять размером шрифта, отступом и радиусом одновременно. Показать все найденные зависимости; отдельно проверить потребителей динамических обращений. Если цифровое имя перестаёт совпадать со значением, показать это в плане, сохранив имя по текущему контракту.

CLI прослеживает статические aliases между JSON-файлами. При одинаковом ключе в разных режимах он консервативно объединяет возможные цепочки и сохраняет путь каждого потребителя; ведущий уточняет фактические сочетания режимов по генератору проекта.

### Типографика

Семейство шрифта не закрепляется за примером AI-PDP-DS. Источник выбирается в брифе: файлы/название/ссылка заказчика, существующий ресурс проекта либо Google Fonts по его указанию. Для подбора без конкретного семейства предложить варианты и согласовать выбор до применения. Самостоятельно назначать Inter/Geologica всем проектам нельзя.

Зафиксировать используемые семейства и роли, реальные начертания/веса, языки, размеры, line-height, letter-spacing и адаптивные режимы по возможностям согласованного фундамента. Часть этих параметров может быть производной; менять её независимо через обход aliases нельзя.

При указании Google Fonts проверить актуальные сведения в официальном каталоге и получить выбранные ресурсы для этого проекта. Импорт не означает автоматическую визуальную приёмку. Для Storybook подключить нужные font-face/пакеты и проверить фактическую загрузку; для Figma проверить доступность семейства и начертаний в целевом файле. Различия CSS font-stack, Figma family/style и числового веса преобразовывать явно. После замены проверить переносы, высоту строк, размеры компонентов и нужные языки.

### Применение и поставка

1. Прочитать заполненный системный бриф и текущий источник токенов.
2. Получить matrix/plan. Проверить неизвестные ключи, типы, единицы, aliases, связанность, полноту палитры и шрифтов. Получить реальное согласование показанного плана; CLI note не удостоверяет личность.
3. Применить значения к примитивам. Устаревший fingerprint требует нового плана. Семантические JSON и aliases должны остаться неизменными.
4. Сгенерировать производные данные локальным генератором проекта. TS/CSS вручную не подменять.
5. Выполнить выбранную поставку и проверки. Сохранить доказательства в задаче проекта. План, apply и сборка не являются приёмкой.

| Поставка  | Действия                                                                                                                                                                                                                                     |
| --------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| storybook | Генерация кода/тем, подключение шрифтов, проверка компонентов, состояний и адаптивности в Storybook. Figma не требуется и не вызывается.                                                                                                     |
| figma     | Значения и aliases применяются в собственной целевой библиотеке через доступный Figma-плагин; типографика и эффекты обрабатываются поддерживаемыми Variables/Styles. React/Storybook-зависимости не устанавливать без отдельной потребности. |
| both      | Один согласованный набор значений преобразуется в код и Figma; обе стороны проверяются по этому набору, включая темы и типографику.                                                                                                          |

Общую эталонную библиотеку не перекрашивать под заказчика. Целевой файл/проект выбирается в брифе; внешние записи выполняются только в порученной поставке. Если шрифт или Figma недоступны, соответствующая проверка остаётся not-run, независимая локальная работа продолжается.

### Локальные команды

Из разработчика выбирать проект явно:

```sh
npm run env:primitives -- matrix --project bank-ds
npm run env:primitives -- plan --project bank-ds --input product-discovery/primitive-request.json
npm run env:primitives -- apply --project bank-ds --input product-discovery/primitive-request.json --expect PLAN_FINGERPRINT --note "Owner approved the displayed plan"
```

Установленный проектный набор предоставляет env:primitives без --project. Команды поддерживают текущий JSON-формат $type/$value: scalar leaf primitives и aliases, перечисленные отдельными строками. matrix/plan ничего не записывают. apply проверяет исходные хеши и меняет только предложенные конечные значения; генерация, подключение шрифтов и Figma-запись выполняются отдельными шагами этой директивы.

## Решения владельца

Согласовать показанный план значений, существенный выбор шрифта и целевую поставку. Не менять отсутствующие параметры/aliases под видом настройки значений. Повторное разрешение на принятый технический шаг не требуется.

## Результат

Согласованные конечные значения внутри выбранного проекта, их происхождение и влияние, производные данные и выбранная поставка. Матрица остаётся представлением токенов, STATE и evidence — внутри задачи.

## Проверка

Проверить сохранность семантики/aliases и фактическое влияние на потребителей. Для storybook выполнить [кодовую поставку](code-delivery.md), для figma — [Figma-поставку](figma-delivery.md), для both — обе и [паритет](figma-parity.md). Типы JSON и fingerprint не подтверждают доступность шрифтов, контраст или визуальную корректность.

## Продолжение и возврат

Устаревший fingerprint требует нового плана. Замечание к значениям возвращает к матрице, независимая новая роль/режим — к изменению фундамента. Повторять затронутые проверки без перекраски master и других проектов. Завершить по [передаче](verify-deliver.md).
