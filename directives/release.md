# Подготовка выпуска

## Назначение и запуск

Использовать после [intake](intake.md) для подготовки конкретного выпуска. Подготовка и внешняя публикация имеют раздельные полномочия.

## Входы

Выбранная система, версия, diff, STATE, полномочия, [релизы](../docs/standards/releases.md) и [качество](../docs/standards/quality.md).

## Условия начала

Известны состав выпуска, целевая версия, поверхность поставки и требования совместимости. Текущие принятые контракты и локальные изменения прочитаны.

## Этапы

1. Оценить публичный API, визуальный контракт, токены, CSS/fonts и совместимость по фактическому diff.
2. Для кодовой поставки подготовить changeset под реальным именем пакета, release notes и миграцию при необходимости. Для Figma-only зафиксировать версию библиотеки, изменения и миграцию в проектных release notes без требования npm-пакета/changeset. Не менять имя/версию соседней системы.
3. Для кодового выпуска пройти [кодовую поставку](code-delivery.md) с release-профилем, упаковкой, изолированной установкой и consumer. Для Figma пройти [Figma-поставку](figma-delivery.md); для both — [паритет](figma-parity.md).
4. Подготовить конкретные артефакты и [экспорт](project-export.md), если он входит в задачу.
5. [Передать](verify-deliver.md) версию, результат, проверки и ограничения. Внешние действия выполнить только при соответствующем явном поручении.

## Решения владельца

Версия/совместимость, существенные изменения контракта, исключения и фактическая публикация. Подготовка выпуска не разрешает commit/push/PR/npm/Chromatic/Figma publish.

## Результат

Проверенный кандидат конкретного выпуска, сведения о совместимости и миграции, фактические артефакты выбранной поставки. Неопубликованное обозначается неопубликованным.

## Проверка

Проверить полноту выбранного release-профиля, содержимое пакета/библиотеки и реальную самостоятельную передачу. Наличие changeset или успешная сборка не доказывают публикацию/приёмку.

## Продолжение и возврат

После изменения кандидата повторить затронутые проверки и обновить evidence. Существенное изменение контракта возвращает к Spec/брифу; для публикации пользоваться только действительными полномочиями на конкретную цель.
