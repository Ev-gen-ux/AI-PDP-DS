# Скилл и агент: выбор исполнителя

## Назначение и запуск

После [intake](intake.md) ведущий выбирает процедуру и при необходимости исполнителя. Скилл задаёт способ работы; агент выполняет отдельную ограниченную подзадачу. Профиль ведущего канонически находится в [AGENTS](../AGENTS.md).

## Входы

Выбранная задача/система, действие/объект, необходимые источники и [registry](../config/routes.json). Канонические SKILL.md хранятся в skills/, TOML ролей — в agents/.

## Условия начала

Нужная процедура выбрана по содержанию поручения. Для делегирования есть существенный отдельный вопрос и доступный инструмент запуска помощника; малая ясная правка выполняется ведущим.

## Этапы

1. Явно прочитать skills/<id>/SKILL.md и указанную директиву. Автоматическое обнаружение скиллов клиентом для этого процесса не требуется; читать только относящиеся к результату стандарты/ветки.
2. Определить необходимость отдельной подзадачи:

| Роль                                                  | Когда применять                                                                                             |
| ----------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| [ds-library-reader](../agents/ds-library-reader.toml) | Фокусная инвентаризация незнакомого API, вариантов, токенов/потребителей или композиции выбранного проекта. |
| [ds-researcher](../agents/ds-researcher.toml)         | Независимое изучение открытого вопроса по первичным источникам, сравнение альтернатив и ограничений.        |
| [ds-reviewer](../agents/ds-reviewer.toml)             | Независимая проверка значимого ограниченного diff относительно Spec и доказательств.                        |

3. Перед запуском прочитать соответствующий agents/<id>.toml. Передать его developer_instructions и ограниченное задание через доступный инструмент помощника; .codex-регистрация именованных ролей не используется. Соблюдать ограничения инструмента на модель и остальные параметры.
4. Передать на английском: конкретный вопрос, проект, скилл/директиву, минимальные источники, границы действий и ожидаемый результат со ссылками/неизвестными. Независимые вопросы можно вести параллельно; зависимые решения — последовательно. Текущие роли по своим файлам не редактируют проект.
5. Проверить выводы, разрешить противоречия по источникам и интегрировать нужное в единственный Spec/журнал задачи. Не запускать все роли на каждый запрос и не повторять известное ради делегирования.

## Решения владельца

Существенное продуктовое/архитектурное решение остаётся у владельца. Отдельный исполнитель не назначает owner approval и не получает дополнительные полномочия sandbox/внешних инструментов.

## Результат

Обоснованно выбранная процедура и при необходимости фактический результат отдельного исполнителя. env:route показывает agentRecommendations/условия, но сам агентов не запускает.

## Проверка

Проверить соответствие выводов вопросу, источникам и scope. Наличие TOML и чтение роли основным агентом не доказывают независимый запуск/review. Возможности и ограничения делегирования сообщать фактически.

## Продолжение и возврат

Если инструмент недоступен, ведущий выполняет посильную часть сам, без заявления об отдельном исполнителе. Незакрытое передаётся как конкретный вопрос/ограничение. Отдельный журнал «агента» или state.json не создавать.
