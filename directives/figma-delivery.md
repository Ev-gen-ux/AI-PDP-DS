# Figma-поставка

## Назначение и запуск

Использовать из системной, компонентной или токенной процедуры для figma/both. Создать или обновить редактируемый результат в собственной целевой библиотеке. Для storybook-only Figma не вызывается. Аудит без поручения исправить идёт по [паритету](figma-parity.md).

## Входы

Бриф, STATE, принятый компонентный контракт, версия фундамента и согласованные значения/изменения; целевой файл, страница/узлы и границы записи. Применять [Figma-стандарт](../docs/standards/figma.md), [компоненты](../docs/standards/components.md), [токены](../docs/standards/tokens.md) и [качество](../docs/standards/quality.md).

## Условия начала

Результат и место записи определены в поручении/брифе. Новый или изменённый компонентный контракт согласован до изменения артефактов. Проверить фактические возможности инструмента и загрузить обязательные доступные Figma plugin skills для чтения, компонентов/переменных и записи. Локальная директива не заменяет контракты инструмента. Новое имя файла или экспорт SVG не являются доказательством готовой библиотеки.

## Этапы

1. Прочитать актуальные целевые узлы, Variables/Styles, свойства и занятое место. Сопоставить источник с текущим состоянием; выявить ручные правки и конфликтующие изменения. Читать по выбранному scope, без бесконтрольного обхода всей библиотеки.
2. Составить конкретный план новых/изменяемых объектов и привязок. Сохранить нужные исходные значения/ID для проверки и безопасного восстановления своей правки. Общий master и чужие элементы не менять ради клиентской настройки.
3. Для value-only настройки применить согласованные значения через [процедуру примитивов](primitive-values.md), сохранив семантику, режимы и alias-цепочки. Явно преобразовать HEX/числа/шрифты в поддерживаемые Figma значения. Эффекты и типографику обрабатывать Variables/Styles по реальным возможностям API.
4. Для компонентов собрать согласованную композицию, auto-layout, свойства и варианты/состояния. Вложенные Label/Inline Message вставить instances существующих компонентов с их собственной семантикой. Тело родителя привязать к его компонентным ролям; не отсоединять вложенные компоненты для перекраски.
5. Проверить наличие требуемых семейств/начертаний перед изменением текста. Отсутствующий шрифт не подменять незаметно. Разместить результат без перекрытий, обрезки и перемещения чужих объектов.
6. После записи повторно прочитать изменённые объекты и выполнить визуальную проверку выбранных состояний/тем/размеров. Сохранить ссылки/ID и фактический результат в задаче проекта. Для both дополнительно пройти [паритет](figma-parity.md).
7. При передаче Figma-only передать собственную библиотеку и проектные документы/источники. Проверить доступность файла получателю. Если запрошен офлайн-файл, использовать доступный экспорт Figma и проверить открытие; недоступную выгрузку отметить not-run. Кодовый env:project export требует React/Storybook-профиль и не служит автоматическим экспортом Figma-only.

## Решения владельца

Целевой файл/место, контракт компонента, новый план примитивов, существенная смена шрифта или структуры. Сохранять уже данные полномочия на запись. Публикация библиотеки и новые внешние действия требуют отдельного соответствующего поручения.

## Результат

Редактируемые компоненты/переменные/стили по порученному scope, ссылки и ID, сведения о привязках, проверках и ограничениях. Готовность Figma и кода отмечается раздельно.

## Проверка

Сверить свойства, матрицу вариантов, композицию, alias-значения, шрифты, auto-layout, темы и реальные размеры с Spec/брифом. Проверить, что изменены только выбранные объекты. Успех write-вызова, наличие component set или Code Connect parse по отдельности не доказывают визуальную корректность и публикацию.

## Продолжение и возврат

При повторном запуске читать актуальное состояние, применять diff и сохранять ручные изменения. При частичном сбое записать, какие ID реально изменены, и восстановить/повторить только свою известную часть; не удалять неизвестные объекты для «чистого» запуска. Конфликт контракта вернуть к Spec, недоступный инструмент/шрифт отметить not-run и продолжать независимую часть. Завершить по [передаче](verify-deliver.md).
