# Передача проекта в отдельную папку или репозиторий

## Назначение и запуск

Использовать для порученной передачи выбранной самостоятельной системы. Кодовый export CLI экспортирует одну папку projects/<id>; разработчик не является зависимостью получателя. Для Figma-only применить отдельную ветку передачи материалов ниже.

## Входы

Проект, его docs/Discovery/Spec, исходники/токены, собственные package/lock/configs/scripts по поставке, существенная история и новый target экспорта. Применять [качество](../docs/standards/quality.md).

## Условия начала

Выбран конкретный проект и новая папка вне источника/коллекции projects. Существующая папка не перезаписывается. CLI поддерживает кодовый профиль: требует собственные package/lock, npm identity, src, tokens, .storybook, docs и scripts; для Figma-only без этого профиля он не применяется. Публикация/репозиторий требуют соответствующего отдельного явного поручения.

## Этапы

1. Подготовить конкретный состав передачи и проверить, что продукт не импортирует инструменты, recovery или конфигурации родителя.
2. Для кодового проекта выполнить CLI экспорт, например:

```sh
npm run env:project -- export ai-pdp-ds --out /private/tmp/ai-pdp-ds-handoff
```

3. Проверить handoff-manifest.json: относительные пути, SHA256, размеры/режимы и fingerprint source snapshot. Абсолютный путь машины не становится зависимостью.
4. Команда исключает .git, приватные .env-файлы кроме .env.example, node_modules, .local, сгенерированные Husky loaders и build/cache outputs. История/исследования/доказательства проекта сохраняются; неизвестные source symlink не обходятся. Состав конкретных исключений сверять с инструментом.
5. CLI экспорт не запускает npm ci/build. Для нужной самостоятельной проверки использовать временную копию по [кодовой поставке](code-delivery.md). Постоянную пробную копию в .local/ не хранить.
6. Для Figma-only передать собственную целевую библиотеку и согласованные проектные материалы по [Figma-поставке](figma-delivery.md). Локальные документы/токены/история остаются в самостоятельной папке проекта; для отдельной копии выбрать новую папку и проверить исключение секретов/кэшей. Не вызывать кодовый export CLI и не создавать фиктивные package/src/Storybook ради него. Если требуется офлайн-файл библиотеки, получить его через реально доступный экспорт Figma и проверить открытие; ссылка на файл такой экспорт не заменяет. Автоматического Figma-only адаптера у export CLI сейчас нет.
7. Если прямо поручен отдельный репозиторий, подготовить и проверить содержимое, исключения, версию и target до фактической записи. Remote, ветка, commit/push и доступы определяются этим поручением; .github экспортированной системы при наличии относится к ней самой.

## Решения владельца

Целевой проект/папка и фактические Git/публикационные действия. Упоминание возможности передачи или запуск export не разрешает их автоматически.

## Результат

Для кодового CLI — новая папка самостоятельного проекта с source manifest. Для Figma-only — переданная библиотека и согласованные проектные материалы; офлайн-файл только при фактическом экспорте. Проверенная поставка и принятый релиз отмечаются только при соответствующих фактических результатах.

## Проверка

Проверить manifest/хеши, отсутствие секретов, кэшей и зависимости от родителя. Сам экспорт не доказывает сборку/установку/подключение пакета. Зафиксировать выполненные проверки и ограничения по [передаче](verify-deliver.md).

## Продолжение и возврат

Повторный экспорт получает новую папку, не затирая предыдущую. При изменении источников перепроверить кандидат и затронутые критерии. Пробные копии очищаются по завершении проверки; Git-данные разработчика в продукт не переносятся.
