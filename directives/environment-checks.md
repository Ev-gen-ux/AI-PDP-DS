# Диагностика среды

## Назначение и запуск

Использовать для проверки структуры разработчика или конкретного журнала. Диагностика читает активные контракты и не назначает продуктовую готовность.

## Входы

Корень среды, config/routes.json, инструкции, стандарты, директивы, metadata/ссылки скиллов, декларации ролей и переносимый набор. При конкретной задаче — её ID/проект либо путь журнала.

## Условия начала

Выбран scope: общая структура или конкретная задача. По умолчанию .local/исторические задачи не сканируются; retired Claude/Cursor-оболочки и migration-архивы не требуются.

## Этапы

1. Выполнить npm run env:check для проверки активного реестра, канонических файлов, ссылок, metadata и состава набора.
2. Проверить нужные декларативные маршруты через env:route --action repair --object component или подходящие действие/объект. Research/parity выбирают процедуру; audit остаётся аудитом.
3. При проверке обычной фразы использовать env:route --request "..." как keyword-подсказку. Она не проводит бриф и не пишет файлы.
4. Для конкретного журнала выполнить env:check --task <task-id> --project <project-id> либо --journal <path> с выбранным --root. Сообщить классификацию stale/consistency без частного текста задачи.
5. По изменённым инструментам выполнить существующие тесты и применимые lint/format. Read-only диагностика не исправляет файлы автоматически.

## Решения владельца

Аудит среды не разрешает её переработку без поручения. Уточнение scope или необходимое изменение правил предъявить до зависимой реализации.

## Результат

Фактические результаты проверок и найденные несоответствия с путями/причиной; ограничения проверки отдельно.

## Проверка

Проверка структуры не доказывает семантическую полноту, визуальный паритет, a11y или передачу всей библиотеки. Скиллы читаются явно; фактический запуск и результат отдельного исполнителя проверяются отдельно от корректного TOML.

## Продолжение и возврат

После порученной правки повторить затронутые проверки. Stale task требует разбора входов и [refresh](task-state.md), который не переисполняет evidence. Будущие доработки самой среды фиксируются в [BACKLOG](../BACKLOG.md); завершить по [передаче](verify-deliver.md).
