# Создание самостоятельной дизайн-системы

## Назначение и запуск

Использовать из [intake](intake.md) для новой системы. Эта директива координирует создание проекта; техническое развёртывание и поставки имеют собственные процедуры.

## Входы

Поручение, имя/ID, исходные материалы и принятые ограничения. Общая архитектура — [ARCHITECTURE](../ARCHITECTURE.md), форма — [системный бриф](../templates/specifications.md#system-brief).

## Условия начала

Определить минимальные вводные для имени/ID и границ. Проверить существующие проекты и отсутствие совпадения; не выбирать другую систему автоматически. До полного брифа достаточно контейнера Discovery.

## Этапы

1. Выполнить npm run env:project -- create <id> --name "<name>". Команда создаёт projects/<id>, system.json и product-discovery с черновым брифом/журналом; существующий проект не перезаписывает и готовую библиотеку не генерирует.
2. Внутри проекта пройти [брифование](briefing.md): потребители, фундамент, поставка, темы, ограничения и критерии. Все продуктовые материалы с начала работы принадлежат этой папке.
3. Провести нужное [исследование](research-design.md); сохранить вопрос, первичные источники, сравнение и выводы в product-discovery/research, решения — рядом в decisions. Кабинетный анализ не выдавать за пользовательский тест.
4. После достаточного согласованного брифа пройти [развёртывание](project-setup.md), затем [настройку примитивов](primitive-values.md). Версия фундамента и состав поставки определяются явно; бренд/история примера не копируются.
5. Создавать компоненты по одному через [компонентную процедуру](component.md). Единственный Spec находится в соседней component-specs/<id>, реализация — в src/components; Discovery не становится складом всех Component Spec.
6. Выполнить [кодовую](code-delivery.md), [Figma](figma-delivery.md) или обе поставки. При both пройти [паритет](figma-parity.md). Для передачи кодового проекта использовать [экспорт](project-export.md); Figma-only передаётся как целевая библиотека и её проектные материалы по Figma-процедуре, без кодового export CLI. Затем [передать результат](verify-deliver.md).

## Решения владельца

Назначение, потребители, версия фундамента, поставка и новые существенные контракты. Не вводить согласование каждого технического шага; пользоваться уже данными полномочиями.

## Результат

Самостоятельная папка выбранной системы с её Discovery, Spec, исходниками/токенами, документацией и необходимой технической средой по поставке. История конкретной системы передаётся вместе с ней.

## Проверка

Проверить фактический результат каждой выбранной поставки, отсутствие parent imports/extends и собственной зависимости от разработчика. Для порученной самостоятельной передачи подтвердить работу изолированной копии. Наличие папки или успешный install-tooling не подтверждает готовность системы.

## Продолжение и возврат

Продолжение восстанавливает текущую задачу; create повторно не вызывается. Замечание возвращается к брифу, фундаменту, Spec или нужной поставке по причине. Другие проекты и общий master автоматически не меняются.
