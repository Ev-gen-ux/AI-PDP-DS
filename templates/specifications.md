# Постановка и спецификации

Канонические формы постановки работы. Ведущий читает нужный раздел и [брифование](../directives/briefing.md); CLI извлекает форму между TEMPLATE-маркерами и снимает внешнее ограждение. Заполненные документы принадлежат проекту. Внутри ограждений ссылки рассчитаны на место готового документа. Не удалять маркеры и ограждения; повреждённая форма отклоняется до записи задачи.

| Раздел                                | Когда                                   | Вход / зависимость                                                                       | Результат                                               |
| ------------------------------------- | --------------------------------------- | ---------------------------------------------------------------------------------------- | ------------------------------------------------------- |
| [system-brief](#system-brief)         | Новая система после минимального intake | Имя/ID и материалы заказчика; [system](../directives/system.md)                          | product-discovery/brief.md                              |
| [brief](#brief)                       | Отдельная новая задача                  | STATE, источники и принятый scope                                                        | brief.md рядом с журналом задачи                        |
| [component-spec](#component-spec)     | Новый/изменённый компонентный контракт  | Достаточный бриф, master/согласованный источник; [component](../directives/component.md) | Единственный component-specs/<id>/spec.md до реализации |
| [primitive-matrix](#primitive-matrix) | Настройка значений                      | Версия фундамента и предложение JSON; [примитивы](../directives/primitive-values.md)     | Представление diff для согласования                     |

Машинная форма — [project/primitive-request.json](project/primitive-request.json). Текущие значения остаются в tokens/primitives проекта; матрица не становится вторым источником. Новый системный бриф не требуется для ясного ремонта. Дальнейшие инструкции — [организация проекта](project-instructions.md).

## system-brief

<!-- TEMPLATE:system-brief:START -->

```markdown
# Бриф дизайн-системы: {{id}}

<!-- BRIEF:DRAFT -->

## Назначение, аудитория и границы

Название/ID, продукты, платформа, состав поставки и критерии готовности. Неизвестные вопросы отделить от уже предоставленных данных.

## Поставка

Выбрать storybook / figma / both. Для Figma определить собственный целевой файл и разрешённые действия. Для Storybook определить способ подключения и передачи кода. Установить темы и адаптивные режимы. Ненужную среду не разворачивать.

## Фундамент

Источник и версия шаблона, перечень семантики, типы, режимы, aliases и связи компонентов. Согласовать code-only/Figma-only различия. Определить, что переиспользуется и какие отдельные изменения фундамента потребуются. Полный технический шаблон разворачивается после достаточного согласованного брифа, внутри этой папки.

## Значения примитивов

Источник данных заказчика: текст/файл/ссылка. Указать сопоставление существующим ключам, сохраняемые базовые значения и открытые вопросы. Использовать процедуру настройки примитивов разработчика; текущие значения хранятся только в tokens/primitives/.

## Типографика

Семейства и роли, начертания/веса, языки, размеры, line-height, letter-spacing и адаптивность по существующему контракту. Источник: заказчик / указанный Google Fonts / существующий ресурс. Требуемый подбор и существенные решения согласуются. Проверки фактических ресурсов, подключения и метрик обязательны для выбранной поставки.

## Шаблон и порядок развёртывания

Зафиксировать выбранный версионированный шаблон. После брифа развернуть его техническую часть, собственные package/lock/scripts/configs, токены и необходимые поверхности проверки. Для storybook/both подготовить запускаемый React/TypeScript/Storybook-каркас; для figma не устанавливать React/Storybook без потребности. Команда create создаёт только контейнер Discovery; install-tooling устанавливает инструменты процесса. Копирование всей истории/бренда AI-PDP-DS не является шаблонизацией.

## Согласование и проверка

Отдельно согласовать примитивный план и новый/изменённый компонентный контракт. Проверить целостность токенов и привязок, контраст, шрифты, состояния, темы, адаптивность и самостоятельную передачу. Сохранить методы, версии, результаты и ограничения в задаче проекта. Открытые блокирующие вопросы должны быть решены перед реализацией.
```

## component-spec

<!-- TEMPLATE:component-spec:START -->

```markdown
# Component Spec: {{component}}

<!-- SPEC:DRAFT -->

## 1. Назначение и источник

Сценарий, Figma master/ревизия или согласованный code-first источник; существенные решения и границы.

## 2. API и Variant Matrix

Props/defaults/варианты/состояния по применимости, композиция и вложенные DS-компоненты.

## 3. Numeric Map

Padding T/R/B/L, gap, radius, typography и цепочка источник → токен → resolved value. Неизвестные значения не заполнять предположениями.

## 4. State Token Matrix

Все применимые состояния: background/border/text/icon/geometry. Семантика вложенных компонентов не копируется в родителя.

## 5. Hard Constraints

Неизменяемые свойства, допустимые настройки и совместимость.

## 6. Поведение и доступность

Клавиатура, фокус, labels, errors/loading, темы/адаптация.

## 7. Verification

Методы/команды, входные версии/хеши, дата, pass/fail/not-run/not-applicable, ограничения и решение владельца. Сборка/parse не заменяют визуальную приёмку/публикацию.
```

## primitive-matrix

<!-- TEMPLATE:primitive-matrix:START -->

```markdown
# Матрица примитивов

Заполняется из фактических tokens/primitives/ и предлагаемого diff. Рабочий источник значений — токены проекта; эта форма используется для согласования, а не для параллельного редактирования значений.

- Фундамент: источник, версия/снимок, согласованные различия между кодом и Figma.
- Поставка: storybook / figma / both; целевые темы, режимы и файл Figma при необходимости.
- Данные заказчика: источник и способ сопоставления параметрам.
- Непредоставленные значения: явно сохраняемые базовые значения или открытый вопрос.

| Ключ | Тип / единица | Текущее | Предложено | Источник | Режимы и потребители | Прямое значение / alias | Решение |
| ---- | ------------- | ------- | ---------- | -------- | -------------------- | ----------------------- | ------- |

Для aliases показывать цепочку и конечный источник; поле редактирования закрыто. Все найденные потребители показываются до применения. Динамические ссылки дополнительно проверяются по коду и макетам.

## Типографика

| Роль/параметр | Семейство / значение | Начертание / вес | Языки | Источник ресурса | Подключение Storybook | Доступность Figma | Решение |
| ------------- | -------------------- | ---------------- | ----- | ---------------- | --------------------- | ----------------- | ------- |

Нет фиксированного обязательного семейства. При отсутствии параметра в фундаменте зафиксировать потребность в отдельном изменении структуры. Не объявлять font assets и рендер проверенными по одному названию шрифта.
```
