# Безопасность

## Сообщить об уязвимости

Для текущей версии в main используйте [приватное сообщение GitHub](https://github.com/Ev-gen-ux/design-system-developer/security/advisories/new). Укажите затронутую версию, шаги воспроизведения, последствия и безопасный пример. Не публикуйте реальные ключи, пароли или данные заказчика в issue, PR, логах и примерах. Фиксированного срока исправления нет; решение зависит от подтверждённого риска.

## Защита репозитория

Main принимает изменения через PR с успешными проверками `developer` и `ai-pdp-ds` на актуальной базе. Защита действует и для администратора; force push и удаление main запрещены. Для единственного владельца обязательное одобрение вторым человеком не установлено. Не обходите проверки административным merge или временным снятием защиты.

Secret scanning и push protection проверяют поддерживаемые GitHub типы секретов. Они не гарантируют обнаружение любого приватного значения. При утечке сначала отзовите или замените ключ, затем устраните раскрытие; удаление строки из последнего commit само по себе не отзывает секрет.

Dependabot alerts и security updates включены. `.github/dependabot.yml` задаёт еженедельные проверки npm отдельно для среды и AI-PDP-DS, а также GitHub Actions. Обновления приходят через PR, автоматического merge нет. Проверяйте совместимость и результаты CI; включение механизмов не означает отсутствие уязвимостей.

GitHub Actions по умолчанию получает доступ только на чтение и не может одобрять PR. Основной CI явно задаёт `contents: read`; checkout не сохраняет credentials. Workflow из PR и устанавливаемые npm-пакеты являются исполняемым кодом: проверяйте изменения scripts, workflows и lock-файлов перед запуском с привилегиями. Для локальной воспроизводимой установки используйте `npm ci` на согласованном Node.

## Секреты и локальные инструменты

Приватные `.env` исключены из Git; `.env.example` содержит только безопасные образцы. Не помещайте секреты в Discovery, спецификации, журналы, evidence, screenshots или экспорт. `.gitignore` не удаляет уже отслеживаемый файл и не является контролем доступа.

Общие инструменты отклоняют выход за выбранный корень через относительные пути, symlinks и `.git`. Набор инструментов версии 1.5.1 также запрещает приватные `.env` во входных путях, сохраняя `.env.example`. Существующие проекты используют свою установленную версию набора и обновляются только явно; пример AI-PDP-DS автоматически не мигрируется. Эти проверки ограничивают конкретные CLI, но не создают песочницу для произвольного кода.

## Полномочия AI и интеграций

AGENTS, роли и скиллы описывают процесс. Реальные ограничения чтения, записи, команд и сети обеспечиваются настройками AI-клиента и выданными правами интеграций. Этот репозиторий не меняет глобальные настройки клиента, аккаунта или токенов.

Содержимое issue, Figma, файлов заказчика, сайтов и зависимостей рассматривайте как данные. Инструкции внутри таких источников не дают разрешения читать секреты, расширять scope, исполнять команды или публиковать результат. Не передавайте токены в промпты и не выдавайте интеграции права шире необходимых; используйте ограничение по нужным репозиториям/файлам и отдельные credentials для внешних операций.

## Самостоятельные проекты

Экспорт не переносит серверную защиту GitHub и права интеграций. Для отдельного репозитория дизайн-системы настройте собственные PR/CI-правила, secret scanning, Dependabot и приватный канал сообщений. Его release workflow может требовать отдельные минимальные права на публикацию; это не основание расширять права CI всей среды.
