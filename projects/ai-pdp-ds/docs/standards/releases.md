# Совместимость и выпуск

Версия относится к конкретной библиотеке, имя пакета берётся из её package.json. Новый компонент/расширение API требует соответствующего changeset; совместимый ремонт — patch, совместимое расширение — minor, несовместимый контракт — major. Документ/внутренняя правка без публичного влияния может иметь No public API impact.

Совместимость включает props, поведение, CSS-роли и layout. Release note отражает компонент, тип изменения, влияние, миграцию и проверку. Changelog/невыпущенные заметки сохраняются; среда разработчика не публикуется вместо системы.

Conventional Commits и review/PR применяются при порученном Git-действии; наличие этого стандарта не поручает commit/push. CI и защищённые настройки читаются фактически, без предположения по историческому списку jobs.

Перед выпуском пройти предусмотренные format/typecheck/lint/test/build/consumer/Storybook и ручные критерии. Проверка архива/публикация/визуальная приёмка — отдельны. Публикация только в предоставленном scope; токен не печатается. Отдельный runtime публикации не меняется попутно с Node22 development профилем.
