# Работа с этой дизайн-системой

Папка самостоятельна: используй только её package/config/scripts, Discovery, Spec и исходники. Проект и имя пакета определяются system.json и package.json; родительская среда не требуется.

Начинай с product-discovery/brief.md и актуального STATE журнала задачи. Один живой spec.md компонента находится в component-specs/<id>, реализация — в src/components/<id>. Последующие задачи компонента имеют собственные brief/журнал в tasks/<id>. Отдельный state.json не создаётся.

Новый/изменённый компонентный контракт согласовывается до кода; ясный ремонт сохраняет принятый API. Вложенные DS-компоненты сохраняют свои props и семантику. Правь исходники токенов, не generated output.

Команды журналов: env:task list/resume/check/update/refresh/approve-spec. Сначала проверяй --help и package scripts. Refresh не превращает старые результаты в PASS. Приёмка требует реального решения владельца о текущей версии.

Проверки выбираются по diff и Spec; pass/fail/not-run/not-applicable фиксируются отдельно. Не выдавай сборку за визуальную/ручную проверку. Не публикуй и не выполняй Git-записи без явного поручения. Секреты не сохраняй.

[Развитие проекта](docs/development.md). Общие инструменты скопированы сюда версионированным набором; их обновление не должно затирать локальные изменения.
